# Triplog 기획서

- 버전: 1.1 / 작성일: 2026-10-31 (KST)
- 상태: 1차 개발용 기획 초안. 확정 요구사항과 구현 제안을 구분한다.
- 서비스명: 트립로그 / triplog

## 1. 목적과 사용 대상

다녀온 장소를 사진·소감·일기로 남기고, 월간·주간·일간·여행별·지도에서 다시 보는 개인 여행 다이어리다. 1차 사용자는 소유자 한 명이며 모든 실제 기록과 사진은 비공개다. 예약·관광 추천 플랫폼이 아닌 여행 기록에 집중한다. 서비스 종료나 운영처 변경에도 기록을 옮길 수 있도록 백업과 내보내기를 중요하게 다룬다.

아이폰을 주 사용 기기로 하는 모바일 우선 웹앱·PWA로 만든다. 여행 중 아이폰 Safari 또는 홈 화면 실행에서 사진·장소·일기를 기록하고, 맥에서는 같은 웹앱을 브라우저로 열어 기록을 조회·수정하고 사진과 긴 글을 정리한다. 별도 macOS 앱은 만들지 않는다.

### 2.1 기기 간 사용과 PWA 기준

- 두 기기는 같은 계정의 서버 기록·사진을 사용한다. 브라우저 localStorage만으로 기기 간 동기화를 대신하지 않는다.
- 아이폰 홈 화면 추가를 위한 앱 이름·아이콘·시작 URL·standalone 표시를 구성하고 안내한다. Safari 접속도 지원한다.
- 아이폰의 사진 선택·한글 입력·키보드·safe area·화면 높이 변화를 우선 확인한다. 맥에서는 넓은 화면 배치와 키보드 접근을 확인한다.
- 서버 저장이 완료된 내용은 다른 기기에서 다시 조회했을 때 일치해야 한다. 실시간 공동편집은 요구하지 않으며 동시 수정 충돌은 감지한다.
- 온라인 사용을 기본으로 한다. 글 초안의 로컬 복구와 서버 저장을 구분하며, 완전한 오프라인 사용·오프라인 지도·백그라운드 사진 업로드·오프라인 사진 업로드 큐는 1차에서 제외한다. 업로드 중 앱을 벗어났을 때의 중단·실패와 재시도를 안내한다.
- 홈 화면 추가·아이폰 실기기 동작·맥 브라우저 동작은 구현 후 각각 검증한다. 반응형 에뮬레이션만으로 실기기 검증을 완료 처리하지 않는다.

## 3. 화면과 정보 구조

주 메뉴는 다이어리 / 여행 / 나의 지도다. 다이어리 내부에 월간 / 주간 / 일간 전환을 둔다. 같은 원본 기록을 각각 다르게 표시하며 화면별로 별도 데이터를 입력하지 않는다. 날짜·여행을 수정하면 관련 화면에 함께 반영한다.

### 3.1 월간

- 한 달 전체 달력을 표시한다. 이전·다음 달 이동 및 날짜 선택을 제공한다.
- 여행 시작일부터 종료일까지 이어지는 옅은 가로 띠를 표시한다.
- **띠 왼쪽의 강조 세로선은 사용하지 않는다.** 옅은 면색으로만 기간을 연결한다.
- 여행 이름은 시작 지점에 표시하고, 주 경계에서 이어지는 기간도 구분 가능하게 한다.
- 기록이 있는 날에는 작은 사진 또는 간단한 표시를 둔다. 긴 글과 여러 장의 사진으로 칸을 채우지 않는다.
- 날짜 선택은 일간, 별도 여행 제목 선택은 여행 상세로 연결하는 방향을 제안한다. 한 버튼 안에 버튼을 중첩하지 않는다.
- 겹치는 여행은 제한된 행으로 표시하고 초과분은 개수로 안내한다.

### 3.2 주간 — 가장 중요한 화면 원칙

**종이 다이어리의 한두 페이지처럼 일주일 전체를 한 번에 보는 화면이다.** 날짜 하나를 선택해 해당 날짜 기록만 보여주는 화면이나, 7일을 길게 스크롤하는 목록으로 대체하지 않는다.

- 7일 고정 칸에 날짜·요일·방문 장소·선택 입력한 시간·작은 대표 사진을 표시한다.
- PC는 펼친 다이어리 두 페이지 구성을 기본으로 한다. 모바일도 7일 전체를 압축해 보여주되 가독성을 유지한다.
- 기록이 많아도 날짜 칸을 무한히 늘리지 않는다. 보이는 개수는 가용 높이에 맞추고 초과분을 '+N개'로 표시한다.
- 긴 소감·일기 본문·큰 사진은 일간에서 본다.
- 날짜 또는 초과 기록 표시를 누르면 해당 일간으로 이동한다.
- 이전·다음 주 이동을 제공하고, 선택 날짜가 포함된 주를 연다.
- 시작 요일(일요일/월요일)은 구현 전 결정한다. 시안은 일요일 시작이다.
- **시안의 주간 화면이 잘리는 문제는 실제 개발의 첫 UI 개선 항목이다.** 헤더·하단 메뉴·안전 영역과 브라우저 주소창을 포함해 가용 높이를 계산하고, 마지막 날짜 및 '+N개'가 잘리지 않아야 한다. 고정 높이와 overflow:hidden만으로 해결하지 않는다.
- 주간이 작아져 글자를 읽기 어려워지면 장식·상단 여백·노출 개수를 먼저 줄인다. 극히 작은 화면에서는 전체 보기와 상세 확대 접근을 제공하는 방안을 검토한다.

### 3.3 일간

- 날짜별 방문 기록 여러 개와 하루 전체 일기를 함께 보여준다.
- 방문 장소마다 사진 여러 장·소감·선택 입력 시간·표시 순서를 둔다.
- 큰 사진과 글을 편하게 읽고 작성·수정하는 화면이다. 내용에 따라 세로 스크롤할 수 있다.
- 이전·다음 날 이동 및 월간·주간으로 돌아가기를 제공한다.
- 시간이 없는 기록도 저장 가능하다. 방문 순서를 직접 정할 수 있다.

### 3.4 여행 목록과 상세

- 여행은 제목·시작일·종료일·대표 사진을 가진다. 지난 여행도 생성할 수 있다.
- 여행별로 일기와 방문 기록을 날짜순으로 모아 보고 해당 여행 지도에 접근한다.
- 기간 변경은 기존 기록을 자동 삭제하지 않는다. 범위 밖 기록은 안내 후 포함 관계를 정리한다.
- 여행 없는 일상·당일치기 기록 허용은 제안 사항이다. 구현 시 여행 연결을 선택 항목으로 설계하면 확장하기 쉽다.
- 한 날짜에 복수 여행을 연결할 수 있을지 결정해야 한다. 날짜만으로 여행을 자동 확정하지 않는다.

### 3.5 나의 지도

- 방문 기록에 위치가 연결되면 별도의 지도 등록 없이 자동으로 표시한다.
- 전체 방문 지도와 특정 여행 지도를 제공하며 기간 필터로 좁혀 볼 수 있다.
- 넓게 보면 가까운 장소를 숫자로 묶고, 확대하면 장소별 사진 썸네일을 표시하는 방향이다.
- 사진 없는 장소는 기본 핀으로 표시한다.
- 핀 선택 → 장소명·방문 날짜·사진·소감 미리보기 → 해당 기록/일간 이동 흐름을 제공한다.
- 같은 장소 재방문은 하나의 장소 아래 여러 방문 이력으로 보여준다.
- Google Maps 연동을 목표로 하되, 기존 시안의 지도는 가상 배치이며 실제 연동 완료로 취급하지 않는다.
- 직접 입력한 장소는 좌표를 지정해야 지도에 나온다. 위치 미지정 기록도 일기에는 저장하고, 지도 제외 상태를 명확히 안내한다.
- 이동 경로 자동 추적은 1차 범위에 없다.

## 4. 기록 작성 흐름

1. 여행을 생성하거나 날짜를 선택한다.
2. 장소 검색 또는 직접 입력으로 방문 장소를 추가한다.
3. 방문 날짜와 필요한 경우 시간을 입력한다.
4. 사진 여러 장과 짧은 소감을 첨부한다.
5. 하루 전체 일기는 별도로 작성한다.
6. 저장된 기록을 월간·주간·일간·여행·지도에서 확인한다.

필수 입력은 방문 날짜와 장소명이다. 시간·사진·소감은 선택 입력을 제안한다. 하루 일기는 장소 없이도 작성 가능하게 한다.

## 5. 사진·날짜·저장 정책 (구현 제안)

- 사진 다중 선택, 순서 변경, 대표 사진 선택, 개별 제거를 제공한다.
- 원본 보관 여부·업로드 크기·개수·허용 형식·압축 수준은 저장 비용을 산정한 후 결정한다.
- 아이폰 HEIC와 사진 회전 정보를 처리하고 미지원 파일·업로드 실패 상태를 안내한다.
- 사진 촬영 날짜는 기록 날짜 제안에만 사용하고 사용자가 수정할 수 있게 한다.
- 방문 날짜는 여행지 기준 날짜로 유지한다. 한국에서 열어도 이전 날짜로 바뀌면 안 된다. 시간이 있으면 해당 시간대도 함께 저장한다.
- 글 자동 저장은 저장 중/완료/실패를 표시하고 실패 시 재시도한다. 업로드 완료 전 사진을 저장 완료로 표시하지 않는다.
- 새로고침·화면 이동·네트워크 실패 후 초안을 복구한다. 브라우저 임시 저장과 서버 저장은 구분한다.
- 1차에는 글 초안의 로컬 복구를 우선하고, 완전한 오프라인 사진 업로드 큐와 오프라인 지도는 후속 검토한다.
- 맥과 휴대폰은 서버의 같은 기록을 읽는다. 동시 수정 시 무조건 덮어쓰지 않고 버전 충돌을 감지하는 방식을 제안한다.

## 6. 데이터 구조 제안

아래는 특정 DB에 종속되지 않는 개념 모델이다. 구현 전 확정한다.

| 개체 | 주요 내용 |
| --- | --- |
| User | 소유자 식별자. 1차 허용 계정만 접근 |
| Trip | 소유자, 제목, 시작일·종료일, 대표 사진 |
| DailyEntry | 소유자, 현지 날짜, 하루 일기, 수정 버전 |
| Place | 소유자 범위의 장소 식별자, 표시 이름, 위도·경도, 외부 장소 ID(있는 경우) |
| Visit | 소유자, 일간 기록, 선택적 여행, 장소, 현지 날짜·시간·시간대, 소감, 순서 |
| Photo | 소유자, 연결 방문/일기, 저장 객체 키, 표시 순서, 대표 여부, 처리 상태 |
| DailyEntryTrip | 필요할 때 하루 일기와 여행 연결. 복수 여행 지원 여부에 따라 단순화 가능 |

장소와 방문을 구분하여 같은 카페에 세 번 방문하면 장소는 하나, 방문 기록은 세 개로 남긴다. 같은 좌표만으로 장소를 강제로 병합하지 않으며, 외부 ID 없는 장소의 중복 정리 규칙을 결정한다. 향후 공유를 위해 소유자·작성자 식별을 남기되 공동편집 시스템을 1차에 만들지 않는다.

## 7. 디자인 기준

- 로고: 개발자 터미널 창 앞을 비행기가 지나가는 심벌과 소문자 triplog 워드마크.
- 정갈하고 읽기 쉬운 고딕체. 모바일에서도 읽을 수 있는 크기와 충분한 대비를 유지한다.
- 생크림색에 가까운 밝은 종이 바탕과 얇은 구분선. 사진이 분위기를 만들게 한다.
- 회색 배경·둥근 카드·파란 버튼이 반복되는 금융/관리 앱 같은 표현을 줄인다.
- 메인 컬러는 몽블랑 디저트 위에 가늘게 짜 올린 밤크림색이다. 갈색과 회색이 조금 섞인 차분한 톤으로, 기존 파란색 중심 방향을 대체한다. 옅은 밤크림은 여행 기간 띠·선택 배경에, 진한 밤색은 버튼·선택 글씨에 사용한다. 색상값은 DECISIONS.md의 초안으로 시작해 실제 화면에서 대비를 검증한다. 과한 감성 문구·손글씨 장식·알약형 요소를 추가하지 않는다.
- 월간은 기간, 주간은 한 주 전체의 방문 흐름, 일간은 큰 사진과 자세한 글로 차별화한다.

## 8. 접근 제어·운영·복구

- 개인 계정만 허용하고 서버에서 모든 기록의 소유권을 검증한다. 로그인 UI만 숨기는 방식은 사용하지 않는다.
- 사진 저장소는 비공개를 기본으로 하고 권한 검증된 다운로드 또는 만료되는 접근 주소를 사용한다.
- 실사용 사진·일기·개인 위치·비밀키를 GitHub 저장소에 커밋하지 않는다.
- Google Maps 키의 사용처·API 범위를 제한하고 호출량·예산을 관리한다. 저장 가능한 장소 데이터와 표시 규칙은 실제 연동 시 공식 약관·정책을 확인한다.
- 미리보기와 운영 데이터·비밀값을 분리한다. 배포 환경만 바꿔 운영 데이터를 덮어쓰지 않는다.
- 삭제 복구 기간과 여행 삭제 시 하위 기록 처리 방식은 결정 전이다. 휴지통과 명시적 확인을 권장한다.
- 내보내기는 기록 JSON(여행·날짜·장소·좌표·소감·사진 연결 관계 포함)과 사진을 묶는 형태를 제안한다. 실제 복원 테스트까지 해야 백업 완료로 본다.
- 비용은 호스팅·DB·사진 저장·전송·지도 호출·선택적 도메인으로 나누어 실제 플랜 확인 후 산정한다. 무료 영구 운영을 가정하지 않는다.

## 9. 개발 순서와 완료 조건

### 단계 A — 화면과 모델 확정

주간 잘림 해결, 월간 세로선 없는 기간 띠, 로고·폰트·반응형 확정. 360px·390px 수준 모바일과 PC에서 확인한다. 주간 마지막 날짜와 초과 표시를 접근할 수 있어야 한다.

### 단계 B — 실제 저장 기반

기술 스택·로그인·DB·사진 저장소를 정하고 여행/일간/방문 CRUD를 구현한다. 저장 후 새로고침·다른 기기에서도 같은 기록이 보여야 한다. 허용되지 않은 계정은 API와 파일에 접근할 수 없어야 한다.

### 단계 C — 사진과 지도

다중 사진·대표 사진·장소 검색·좌표 지정·전체/여행/기간 필터 지도를 구현한다. 같은 장소 재방문, 사진 없는 장소, 좌표 없는 기록, 장소 검색 실패를 확인한다. 저장/삭제 시 달력과 지도에 일관되게 반영해야 한다.

### 단계 D — 안정화와 배포

자동 저장·초안 복구·업로드 재시도·삭제 복구·내보내기/복원을 검증한다. Vercel 배포와 환경변수·저장소 권한·비용 한도를 확인하고 운영 절차를 README에 기록한다.

### 핵심 수용 시나리오

- 아이폰 Safari와 홈 화면 실행에서 저장한 기록·사진을 맥 브라우저에서 다시 읽고 수정하며, 아이폰에서 다시 조회했을 때 수정 내용이 일치한다.
- 아이폰 홈 화면의 이름·아이콘·시작 화면이 올바르고, 키보드 및 safe area 때문에 입력·저장·주간 마지막 날짜가 가려지지 않는다.
- 5일 여행이 월간 가로 띠로 이어지고 왼쪽 세로선은 없다.
- 한 주에 기록이 많아도 7일 칸이 유지되며 초과 기록이 숨겨진 채 사라지지 않는다.
- 같은 날 세 장소를 저장하고 장소별 사진·소감과 하루 일기를 각각 다시 볼 수 있다.
- 주간 날짜/지도 핀에서 해당 일간 기록으로 이동한다.
- 같은 장소를 다른 날 다시 방문하면 지도 장소 하나에서 두 이력을 확인한다.
- 여행 기간을 수정해도 기존 기록이 소실되지 않는다.
- 해외 날짜가 귀국 후에도 유지된다.
- 저장 실패를 성공으로 안내하지 않으며 새로고침 후 초안을 복구한다.
- 서버 기록과 사진을 내보낸 뒤 관계를 보존해 복원할 수 있다.
