# triplog 디자인 의사결정

중요한 시각·상호작용 결정만 기록한다. 기능·운영 정책은 [기존 개발 결정](../DECISIONS.md)에 보존한다. 현재 토큰의 단일 기준은 [디자인 시스템](DESIGN_SYSTEM.md)이며 과거 초안과 다르면 최신 승인 기록을 따른다. 사소한 간격 수정은 기록하지 않아도 된다.

## Decision: Mont Blanc Cream

- Date: 2026-10-31
- Status: Approved
- Decision: Quiet Travel Archive — Mont Blanc Edition을 적용하고 기본 포인트를 Mont Blanc Cream으로 지정한다. 흰색을 기본 배경으로, 크림·아이보리는 필요한 강조 면으로 사용한다. Core Palette는 디자인 시스템의 승인된 다섯 토큰을 따른다.
- Rationale: 여행을 소비하는 서비스보다 개인의 사진과 기억을 보관하는 따뜻하고 정갈한 아카이브에 맞춘다.
- Rejected Alternatives: Blue-centered accent system, 이전 몽블랑 팔레트 초안의 HEX를 계속 현재값으로 사용하는 방식, 화면 전체를 베이지 카드로 구성하는 방식.
- Affected Areas: Theme, navigation, calendar selection, buttons, focus and active states, browser/PWA background. 기존 에셋은 보존한다.
- Constraints: 대비 검증, 사진·지도 본래 색과 의미 유지. 크림 위 흰 글자 금지. 작은 텍스트에 text-muted, 크림 위 accent-strong을 그대로 쓰지 않고 디자인 시스템의 허용 조합을 따른다. Supporting/상태 토큰은 초기 제안이며 Core 승인과 구분한다.
- Compatibility: 기존 밤크림 방향을 구체화하며 `docs/DECISIONS.md`의 이전 HEX 초안을 대체한다. SUIT·얄쌍한 로고·개발자 터미널/비행기 콘셉트·월간 세로선 없는 기간 띠·주간 7일 목적은 유지한다.
- Implementation: 문서 승인. 이 PR에서는 CSS·PWA·로고·화면을 변경하지 않는다. 실제 적용에는 승인된 UI 범위와 브라우저 검증이 필요하다.

## Decision: SUIT와 로고 보존

- Date: 2026-10-31
- Status: Approved (기존 선택 재확인)
- Decision: SUIT 자체 호스팅을 유지한다. 본문 400, 제목·선택 500, 필요한 강조 600을 기준으로 얄쌍하고 읽기 쉬운 위계를 만든다. 구체적인 크기·행간은 디자인 시스템의 반응형 기본 제안이다.
- Rationale: 한글·영문의 일관성과 정갈한 개인 여행 수첩의 인상을 유지한다.
- Rejected Alternatives: 장식 폰트·다른 본문 패밀리 혼용, 볼드 남발, 가독성을 희생한 작은 글자, 로고 임의 재제작.
- Affected Areas: 제목·본문·입력·날짜·캡션. 기존 로고 파일·아이콘·문서용 SVG의 원본 지위는 바꾸지 않는다.
- Constraints: 기존 에셋 보존, 본문 가독성·실제 폰트 로딩 검증. 과거 제목 300/400 비교 제안보다 새 기본 위계를 우선하되 기존 화면을 이번에 일괄 변경하지 않는다.

## Decision: UI 설계 승인과 리뷰 분리

- Date: 2026-10-31
- Status: Approved
- Decision: 신규/대규모 UI는 맥락 분석 → 최대 3가지 실질적 방향 비교 → 사용자 선택·승인 → 구현 → 시각 검토 → 중요도순 개선으로 진행한다. 설계와 리뷰 스킬을 저장소에서 관리한다. 작은 수정은 간소화하고 기존 승인을 반복 요청하지 않는다.
- Rationale: 일반적인 AI 화면 패턴을 반복하기보다 승인된 정보 구조와 경험을 축적한다.
- Rejected Alternatives: 색만 다른 시안, 사전 승인 없는 전체 리디자인, 리뷰 요청 중 임의 코드 수정.
- Affected Areas: AGENTS, 프로젝트 UI 설계·리뷰 스킬, 새 화면·대규모 변경 PR.
- Constraints: 리뷰 전용 실행은 읽기 전용. 실제 검증과 미검증을 구분한다. Critical/Major/Minor로 보고하며 기능 범위·DB/API 계약을 확대하지 않는다. #22 세로형 위클리와 #1 미결정 정책을 이번 승인에 포함하지 않는다.

## Decision: 여행 목록 수정 A와 간결한 조회 조건

- Date: 2026-11-01
- Status: Approved (사용자 선택)
- Decision: #4의 여행 목록은 목록 → 상세 → 별도 작성/수정 흐름을 사용한다. 사용자가 선택한 수정 A처럼 390px에서 128×96 가로형 사진을 제목·기간·동행자 옆에 둔다. 320px에서는 긴 한글 가독성을 위해 사진을 104×78로 줄인다. 사진 없는 여행은 빈 사진칸 없이 표시한다.
- Rationale: A의 여행 목록 밀도를 보존하며 사진의 비중을 높인다. #25 Quiet Travel Archive의 사진·글·날짜 위계와 얇은 구분선을 따른다. 상세는 큰 대표 사진과 날짜별 글을 구분하고 반복 카드·그림자를 추가하지 않는다.
- Rejected Alternatives: 기존 A의 작은 64×64 사진, 목록마다 큰 사진을 쌓고 상세 안에서 바로 편집하는 B.
- Affected Areas: `/trips`, `/trips/new`, `/trips/[id]`, `/trips/[id]/edit`, 여행 상세의 지도 진입과 메뉴 활성 상태.
- Follow-up approval: 사용자가 조회 영역의 높이를 줄이고 검색어·기간·동행자로 조회하도록 요청했다. 여행 제목 검색을 기본으로 표시하고 기간·동행자는 접을 수 있는 상세 조건에 둔다. 조건을 함께 적용하며 기간은 양 끝을 포함한 겹침, 동행자는 저장된 이름 선택으로 조회한다. 접힌 상태에도 적용된 조건 개수를 표시한다.
- Constraints: 새 승인 팔레트는 여행 화면 범위에 적용하며 기존 주간 7일·월간 정책·로고는 보존한다. 사진은 저장소의 예시이며 실제 업로드가 아니다. 인증 보류에 따라 가상 여행만 브라우저에 저장하고 서버 저장·실제 지도·사진 업로드·이동편 편집을 구현 완료로 취급하지 않는다. 이번 변경은 #25 전체 화면 디자인 완료를 의미하지 않는다.

## Decision: 일간 B와 수정 버튼으로 여는 입력 폼

- Date: 2026-11-01
- Status: Approved (사용자 선택 및 보완)
- Decision: #5 일간은 하루 일기 → 다녀온 장소 순서로 읽고, 각 영역의 `수정` 버튼을 눌렀을 때만 해당 입력 폼과 저장·취소 버튼을 표시한다. 빈 일기는 `작성`, 새 방문은 `방문 추가`로 시작한다. 한 번에 한 영역만 편집한다.
- Rationale: 사용자는 B의 같은 화면 작성 흐름을 선택하고, 평소에는 입력란을 숨기고 수정 버튼으로 열도록 요청했다. 전체 편집 화면 이동 없이 필요한 일기나 방문만 수정할 수 있다.
- Rejected Alternatives: A의 별도 편집 화면·하루 전체 일괄 저장, B 초안처럼 일기 입력란을 항상 노출하는 방식.
- Affected Areas: `/diary/[date]`의 일기·방문 조회/입력, 방문 순서·날짜 이동, 주간·여행 상세의 동일 가상 기록 조회. 사진은 작은 미리보기와 펼쳐 보는 큰 사진을 제공한다.
- Constraints: 인증 보류에 따라 가상 기록만 브라우저에 저장한다. 실제 서버 저장·기기 간 동기화·장소 검색/좌표 지정·사진 업로드는 포함하지 않는다. 날짜는 현지 날짜 문자열로 보존하고, 여행은 직접 선택한 연결만 사용한다. 저장 실패·변경 충돌 때 입력을 유지하며 자동 저장·초안 복구는 #9로 남긴다. 주간 7일·미결정 #22 배치는 보존한다.

## Decision: 월간 B와 선택 날짜 미리보기

- Date: 2026-11-07
- Status: Approved (사용자 선택)
- Decision: #6 월간은 한 달 달력과 세로 강조선 없는 여행 기간 띠를 표시하고, 날짜를 선택하면 달력 아래에 방문·사진·일기 요약을 보여준다. `일간 보기`에서 상세 조회·편집으로 이동한다. 월간·주간·일간은 같은 가상 기록을 읽는다.
- Rationale: 사용자는 날짜에서 곧바로 일간으로 이동하는 A보다 선택 날짜를 월간 안에서 먼저 확인하는 B를 선택했다. 달력에는 작은 기록 표시를 두고 사진과 글은 아래에 모아 좁은 날짜 칸을 간결하게 유지한다.
- Rejected Alternatives: A의 날짜→일간 직접 이동과 날짜 칸별 작은 사진, 선택 날짜마다 일간 편집 폼까지 월간에 복제하는 방식.
- Affected Areas: `/?view=month&date=YYYY-MM-DD`, 월간·주간·일간 사이 이동, 여행 상세 링크. 월요일 시작은 기존 미확정 시안을 유지한다.
- Constraints: 기간 띠는 두 줄까지 표시하고 초과 여행은 펼쳐 접근한다. 띠의 줄임 제목은 접근 가능한 이름과 선택 날짜 아래의 전체 여행 목록으로 보완한다. 여행 기간과 일기·방문에 명시적으로 연결한 여행은 구분하며 날짜로 연결을 만들지 않는다. 실제 서버 저장·사진 업로드·지도·인증은 이번 범위에 포함하지 않는다.

## Decision: 이동편 B와 별도 입력 화면

- Date: 2026-11-07
- Status: Approved (사용자 선택)
- Decision: #23 이동편은 여행 상세에서 목록을 읽고 추가·수정 시 별도 화면으로 이동한다. 출발·도착 공항/역, 현지 날짜·시각, 각 IANA 시간대를 나눠 입력하며 저장·취소 후 해당 여행 이동편 목록으로 돌아온다.
- Rationale: 사용자가 B를 선택했다. 긴 날짜·시간대 입력을 여행 상세와 분리해 한 구간의 입력과 검증에 집중한다. 목록에서 수동 순서를 바꾸고 확인 후 개별 구간을 삭제한다.
- Rejected Alternatives: A의 여행 상세 목록 안에 긴 수정 폼을 펼치는 방식, 입력 폼을 목록에 항상 노출하는 방식.
- Affected Areas: `/trips/[id]/segments/new`, `/trips/[id]/segments/[segmentId]/edit`, 여행 상세 이동편 목록과 기간 밖 안내·삭제 제한.
- Constraints: 가상 기록의 브라우저 저장 기준이다. API 국가/노선·제공자·비용·보관 조건은 미확정이며 실제 운행정보 검색·서버 저장은 포함하지 않는다. 날짜변경선 이동은 현지 날짜와 실제 시각을 모두 보존하고 서머타임 중복 시각은 실제 UTC 시각을 선택한다. 현행 서버 모델은 현지 시각·시간대만 저장하므로 실제 저장 연결 전에 중복 시각 선택도 보존하는 계약을 검증해야 한다. 오류·저장 실패·탭 충돌 시 입력을 유지하며 실제 Safari 검증은 #11에서 진행한다.

## Decision: 사진 편집 A 흐름과 B 대표 설정의 조합

- Date: 2026-11-12
- Status: Approved (사용자 선택 및 수정안 승인)
- Decision: 일간 방문 안에서 사진 편집을 열고 사진 변경만 저장·취소한다. 대표 설정은 큰 대표 미리보기 아래 번호·파일명·현재 대표가 있는 B의 세로 목록을 사용한다. 사진이 없으면 A처럼 빈 이미지 틀 없이 안내와 `사진 추가`를 표시한다. 평소에는 큰 사진·썸네일·소감을 읽고 편집 도구는 숨긴다.
- Rationale: 사용자는 A의 일간 안 편집 흐름과 빈 상태, B의 대표 사진 설정을 선택했다. 대표 사진과 표시 순서는 독립적으로 바꾸며 대표 제거 시 남은 첫 사진을 대표로 지정한다.
- Rejected Alternatives: 별도 사진 관리 화면으로 이동하는 B 전체 흐름, 사진마다 모든 조작을 반복하는 A 초안, 선택한 한 장에만 공통 조작부를 두는 수정안.
- Affected Areas: 일간 방문 사진의 읽기/편집, 주간·월간 대표 사진, 여행 날짜별 방문 사진 미리보기. 여행 자체의 대표 사진 선택은 유지한다.
- Constraints: 인증 전 가상 기록만 사용하며 기존 예시 사진 2장에서 여러 장을 선택한다. 실제 파일 선택·업로드·HEIC/회전·압축·서버 저장·기기 간 동기화는 포함하지 않는다. 원본·형식·용량·개수 제한은 미확정으로 유지한다. 기존 한 장짜리 브라우저 기록을 보존하고 저장 실패·다른 탭 변경 시 입력을 유지한다. Safari 실기기 검증은 #11에 남긴다.
