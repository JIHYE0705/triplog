# triplog UI 리뷰

경로는 저장소 루트 기준이다. `AGENTS.md`, `docs/design/DESIGN_SYSTEM.md`, `docs/design/DECISIONS.md`와 대상 화면의 PRD·관련 Issue·승인 방향을 읽는다. 코드·연결된 컴포넌트·실제 스타일·데이터 상태를 확인한다. 스크린샷만 제공된 경우 보이는 내용과 확인할 수 없는 동작을 구분한다.

**리뷰만 요청된 실행에서는 코드·문서·에셋을 수정하거나 커밋하지 않는다.** 구현 후 자체 검토에서 수정까지 승인된 경우에만 해당 범위의 문제를 고친다. 리뷰를 이유로 전체 리디자인·기능 추가를 진행하지 않는다.

검토 기준:

- 개인 비공개 아카이브의 인상, 소문자 triplog·기존 로고 보존, 흰 배경·크림 포인트·SUIT·얇은 구분선과 승인 토큰. 보조/상태 색의 제안 상태와 실제 대비를 확인한다.
- 카드 반복·베이지 면 과다·그림자·그라데이션·무의미한 배지/숫자/아이콘·장식/애니메이션·SaaS 구조·추천/예약/마케팅 문구의 필요성을 평가한다. 존재만으로 결함이라 하지 말고 행동·탐색·가독성에 미치는 영향을 근거로 삼는다.
- 주요 행동·날짜·장소·사진·캡션·긴 일기의 위계, 정보 밀도·읽기 폭·한글/영문 줄바꿈. 사진 없는 기록·빈 날·다량 기록·긴 장소명·주/월 경계를 포함한다.
- 주간의 7일 전체·마지막 날짜·+N개·일간 이동, 월간의 세로선 없는 기간 밴드, 사진과 기록의 자연스러운 비율, 여행·지도·작성 흐름의 기존 계약. 없는 기능을 있다고 가정하지 않는다.
- 320/360/390px·데스크톱·낮은 높이/가로 화면·safe area·주소창/키보드·200% 글자 확대. 주요 터치 44px 제품 목표와 WCAG AA 최소 기준은 구분한다.
- 실제 전경/배경 대비, 포커스 표시·가림·순서, 접근 가능한 이름·입력 label·키보드 조작, 색 이외의 상태 단서, Hover/Focus/Active/Disabled 및 Loading/Empty/Error. 크림 위 흰 글자, 작은 text-muted, 크림 위 accent-strong의 제한을 확인한다.

가능하면 기존 실행·검증 도구로 실제 브라우저를 열어 정상/빈/오류·키보드 흐름을 확인하고 스크린샷을 검토한다. 개인 데이터 대신 가상 데이터를 사용한다. 브라우저·실기기·외부 연동이 없으면 코드/이미지 기반 검토임을 명시하고 전체 접근성·실기기 통과를 선언하지 않는다.

결과는 중요도순으로 보고한다:

- **Critical:** 기능 중단·핵심 기록 접근 불가·접근성 문제.
- **Major:** 사용성·레이아웃·가독성 문제.
- **Minor:** 세부 간격·정렬·시각 완성도 문제.

각 문제에 위치(파일/화면·요소), 재현 조건·관찰 근거, 사용자 영향, 가장 작은 개선안을 쓴다. 미확인 우려는 발견 사실과 구분한다. 문제가 없으면 억지로 만들지 않는다. 실행한 검사·화면 크기·스크린샷 위치와 미검증·한계를 함께 보고한다. 수정이 승인된 경우 중요한 문제부터 고치고 관련 동작·시각 상태를 재검토한다.
