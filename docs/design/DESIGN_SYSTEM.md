# triplog 디자인 시스템

기준일: 2026-10-31. **Quiet Travel Archive — Mont Blanc Edition**.

이 문서는 UI의 시각 언어와 검토 기준이다. 기능 범위·우선순위는 [PRD](../PRD.md), [인수인계](../CODEX_HANDOFF.md), [개발 결정](../DECISIONS.md), 관련 Issue와 [진행표 #12](https://github.com/JIHYE0705/triplog/issues/12)를 따른다. 승인 이력은 [디자인 결정](DECISIONS.md)에 남긴다. 이 문서 작성은 앱에 토큰을 적용하거나 기능을 구현했다는 뜻이 아니다.

## 브랜드와 콘텐츠

triplog는 개인 비공개 여행 아카이브다. 여행 경험을 시간순으로 보관하고 날짜·장소·사진·일기·감상·동행자·이동편을 연결한다. 달력과 지도는 과거의 기록을 다시 발견하는 도구다. 예약·관광 추천·소셜 피드는 만들지 않는다.

Quiet / Editorial / Minimal / Warm / Timeless / Personal / Refined. 고급스럽고 정갈하되 차갑지 않게, 감성은 사진과 기록·정보 배치에서 만든다. 스크랩북 장식이나 랜딩페이지 슬로건을 더하지 않는다. 긴 한글과 영문 장소명·현지 날짜를 자연스럽게 읽을 수 있어야 한다.

- 브랜드 표기는 소문자 `triplog`. 기존 얄쌍하고 정갈한 로고와 **개발자 터미널** 앞을 지나는 비행기 콘셉트를 보존한다. 공항 건물로 재해석하지 않는다.
- 기존 로고·아이콘·문서 SVG를 재제작하지 않는다. 저장소의 코드 기반 아이콘과 문서용 SVG를 승인된 최종 원본으로 간주하지 않는다.
- 사진·지도 본래 색상과 지도 제공자의 의미·출처 표시를 유지한다. 사진에 일괄 베이지 필터를 씌우지 않는다.
- 화면·메뉴 이름은 기존 결정대로 다이어리·여행·지도. 요청서의 ‘나의 지도’는 설명용 표현이며 메뉴명 변경 승인이 아니다.

## 색상 토큰

토큰명은 의미 기준이다. 현재 CSS 변수명과의 매핑은 아래 적용 차이 표를 따른다. 새 UI 구현 시 이 값을 사용하되, 기존 스타일 전체 치환은 별도 승인된 범위에서 진행한다.

| Token | 이름 | 값 | 용도·상태 |
| --- | --- | --- | --- |
| accent-primary | Mont Blanc Cream | `#E9DDC7` | 주요 강조 면, 승인 |
| accent-soft | Soft Ivory | `#F8F3E9` | 선택 영역·은은한 구분 면, 승인 |
| accent-strong | Chestnut Brown | `#79634F` | 활성 요소·강조 텍스트, 승인 |
| text-primary | Warm Ink | `#302B27` | 제목·본문, 승인 |
| bg-primary | Paper White | `#FFFFFF` | 전체 기본 배경, 승인 |
| bg-secondary | — | `#FAF8F4` | 보조 배경, 초기 제안 |
| border-default | — | `#E8E3DB` | 장식적 구분선, 초기 제안 |
| text-secondary | — | `#6F6A63` | 부가 정보, 초기 제안 |
| text-muted | — | `#817B73` | 제한적 저위계 표현, 초기 제안·아래 대비 제한 필수 |

흰색을 화면의 대부분으로 유지하고 크림·아이보리는 필요한 곳에만 쓴다. 모든 화면에 강조색 비율을 강제하거나 베이지 카드를 가득 채우지 않는다. 파란색 중심 강조는 폐기한다. 상태·지도·사진의 의미상 색상은 이 규칙과 구분한다.

### 상태 색상 — 구현용 제안

| Token | 값 | 의미 |
| --- | --- | --- |
| status-success | `#2F6B4F` | 서버 저장·처리 성공 |
| status-warning | `#805B16` | 주의·사용자 확인 필요 |
| status-error | `#A33A32` | 저장·조회 실패, 오류 |

상태 색상은 브랜드 강조색으로 대체하지 않는다. 문구·아이콘·입력 오류 설명 등을 함께 제공한다. 서버 저장과 브라우저 임시 보관, 사진 업로드 진행을 구분한다. 성공·경고·오류 색상은 흰 배경의 텍스트로 각각 약 6.29 / 6.13 / 6.54:1이며 다른 배경에서는 재검증한다. 이 값은 제품 브랜드의 추가 확정 결정이 아니다.

### 대비와 허용 조합

WCAG 2.2 AA 목표: 일반 텍스트 4.5:1, 큰 텍스트 3:1. 큰 텍스트는 대략 24 CSS px 이상(또는 약 18.67px 굵은 글자)이며 20px Medium 제목을 큰 텍스트로 간주하지 않는다. 컨트롤과 상태를 식별하는 필수 시각 정보는 인접색과 3:1을 확인한다. 장식적 구분선과 비활성 요소는 구분해서 평가한다.

아래는 불투명 sRGB HEX의 상대 휘도로 계산한 값이며 표시만 소수 둘째 자리로 반올림했다. 통과 판정에는 반올림 전 값을 사용한다. 실제 브라우저의 투명도·합성 배경·포커스·비활성 상태 검증을 대신하지 않는다.

| 전경 / 배경 | 대비 | 사용 |
| --- | --- | --- |
| text-primary / bg-primary | 14.00:1 | 본문·제목 |
| text-primary / accent-primary | 10.42:1 | 크림 버튼·선택 면의 글자 |
| text-secondary / bg-primary | 5.36:1 | 작은 보조 문구 |
| text-secondary / accent-soft | 4.85:1 | 아이보리 위 보조 문구 |
| accent-strong / bg-primary | 5.66:1 | 활성 글자·포커스 |
| accent-strong / accent-soft | 5.12:1 | 선택된 날짜 글자 |
| bg-primary / accent-strong | 5.66:1 | 진한 버튼 위 흰 글자 |
| text-muted / bg-primary | 4.19:1 | 일반 크기 텍스트 불가. 의미 있는 작은 문구는 text-secondary 사용 |
| accent-strong / accent-primary | 4.21:1 | 일반 크기 텍스트 불가. text-primary 사용 |
| text-secondary / accent-primary | 3.99:1 | 일반 크기 텍스트 불가. text-primary 사용 |
| bg-primary / accent-primary | 1.34:1 | 흰 글자 금지 |
| border-default / bg-primary | 1.28:1 | 입력 경계·선택 상태의 유일한 식별 수단으로 사용 금지 |

크림 면 자체도 흰 배경과 1.34:1이므로 단독으로 필수 선택 상태를 전달하지 않는다. 선택된 날짜·탭에는 명확한 글자·밑줄·테두리와 `aria-current` / `aria-selected` 등 해당 시맨틱을 함께 쓴다. 입력창이 경계로 식별되는 경우 진한 테두리 등 3:1 단서를 사용한다. 색상만으로 오류를 전달하지 않는다.

기준: W3C [텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

## 타이포그래피

기본은 **SUIT**, 본문 400, 제목·선택 상태 500, 필요한 강조에만 600. 700 이상을 반복하지 않는다. 얇은 인상을 위해 본문을 300 이하로 낮추거나 작은 글자·낮은 대비를 강제하지 않는다. 로고는 기존 에셋을 보존한다.

`app/fonts/SUIT-Variable.woff2`와 `next/font/local`, `--font-suit` / `--font-sans`를 재사용한다. 폰트 출처·라이선스는 [폰트 안내](../../app/fonts/README.md)를 따른다. 외부 CDN·새 폰트 의존성을 추가하지 않는다.

| Token | 크기 | 굵기 | 권장 행간·역할 |
| --- | --- | --- | --- |
| type-caption | 12px | 400 | 1.5, 사진 캡션·짧은 부가 정보 |
| type-secondary | 14px | 400 | 1.6, 보조 정보 |
| type-body | 16px | 400 | 1.8, 본문·입력 |
| type-section-title | 20px | 500 | 1.4, 영역 제목 |
| type-page-title | 28px | 500 | 1.4, 페이지 제목 |

크기·행간은 기본 제안이며 화면 목적과 반응형에 맞게 조정하고 같은 역할의 위계를 유지한다. 날짜·장소명을 구분하고 사진 캡션은 본문보다 낮게 둔다. 긴 일기는 약 60~70ch 이내 읽기 폭부터 검토한다. 긴 한글·영문·시간대와 확대 상태에서 줄바꿈을 확인한다. 필수 시간·장소 정보를 10~11px에 의존하지 않는다.

## 레이아웃과 공통 컴포넌트

- 모바일 우선. 주요 검토 폭 390px, 추가 320/360px 및 데스크톱. 낮은 높이·가로 화면·브라우저 주소창·safe area·키보드·글자 확대를 고려한다. 넓은 화면에서도 읽기 폭을 제한한다.
- 간격 토큰 `space-1…7`: **4 / 8 / 12 / 16 / 24 / 32 / 48px**. 과도한 빈 공간보다 화면의 행동·정보 밀도에 맞춰 배치한다.
- 테두리 `border-width-default: 1px`. 반경 `radius-small: 4px`, `radius-default: 8px`부터 검토한다. 사진·독립 콘텐츠에 다른 값이 필요하면 이유를 남긴다. 모든 요소를 같은 라운드로 만들지 않는다.
- 기본 그림자 없음. 실제 겹치는 레이어 구분에만 사용한다. 기존 `Navigation`, `WeeklyDiary`, 날짜 유틸리티와 클래스 구조를 먼저 읽고 재사용한다. 새 공통화·UI 라이브러리는 실제 필요가 있을 때만 검토한다.

| 상태·요소 | 기준 |
| --- | --- |
| 기본 버튼 | 크림 면 + Warm Ink 또는 Chestnut 면 + 흰 글자. 동작 위계에 따라 선택 |
| Hover | 은은한 아이보리·밑줄 등으로 조작 가능성을 표현, 터치에서 hover에 의존하지 않음 |
| Focus | 인접 배경 대비를 확인한 명확한 외곽선, 가림·잘림 없이 표시 |
| Active·선택 | 진한 글자·선/형태 + 적절한 시맨틱, 선택·오늘·현재 페이지를 구별 |
| Disabled | 비활성 속성과 이유 안내, opacity로 필수 안내까지 흐리게 하지 않음 |
| Loading | 진행 문구와 필요한 상태 알림, 중복 저장 방지·작성 내용 보존 |
| Empty | 아직 기록이 없음을 담백하게 안내, 구현된 경우에만 다음 행동 제공 |
| Error | 실패 위치·재시도 안내, 원문·사진 선택 보존, 성공으로 표시하지 않음 |

버튼·입력은 접근 가능한 이름과 실제 label을 제공한다. 아이콘만 있는 조작에도 이름을 붙인다. 탭·버튼·링크 시맨틱, 키보드 순서, 대화상자 포커스 복귀를 지킨다. 독립적인 주요 터치 조작은 44×44px을 제품 목표로 한다. WCAG 2.2 AA의 [최소 타깃 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)은 24×24px 또는 규정된 간격·예외이며 44px을 AA 최소치로 잘못 보고하지 않는다.

둥근 카드 반복·과한 그림자·보라/파랑 그라데이션·의미 없는 통계·배지/아이콘 남발·유리 질감·목적 없는 애니메이션·SaaS 관리자 구조·추천/예약 버튼·마케팅 문구를 기본값으로 쓰지 않는다. 실제 사용자 행동에 필요한 예외는 이유를 설명하고 제한적으로 적용한다.

## 화면별 기준

| 화면 | 우선 행동과 지켜야 할 구조 |
| --- | --- |
| 월간 | 여행 기간을 세로 강조선 없는 옅은 가로 밴드로 연결. 시작 지점 여행명, 주/월 경계·겹침·초과 접근. 날짜→일간, 여행명→상세를 중첩 버튼 없이 구분 |
| 주간 | 7일 전체·작은 사진·장소·선택 시간, 기록 많으면 압축 +N개→일간. 마지막 날짜를 숨기지 않음. 높이·여백·노출 수부터 조정하며 글자만 줄이지 않음 |
| 일간 | 큰 사진·장소별 소감·하루 일기를 구분, 긴 글 가독성, 이전/다음 날짜·주간 복귀 |
| 여행 | 대표 사진·여행명·기간·선택 동행자 이름·일별 탐색·이동편 연결. 가격·평점·예약 표현 금지 |
| 지도 | 전체/여행/기간의 방문 장소, 사진 없는 핀·밀집 장소 묶기·재방문 이력·일간 이동. 위치 없는 기록은 보존하고 지도 제외 안내. 관광 추천 금지 |
| 기록 작성 | 사진·일기 흐름, 명확한 날짜·장소, 선택 동행자·이동편. API 실패 시 수동 입력. 저장 중/실패/재시도·초안과 서버 저장을 구분 |

이는 화면의 품질 기준이며 신규 기능 구현 승인이 아니다. 동행자는 [#4](https://github.com/JIHYE0705/triplog/issues/4)의 여행별 이름이며 계정 초대·공동 기록과 다르다. 이동편·수동 입력은 [#23](https://github.com/JIHYE0705/triplog/issues/23), 작성·초안은 #5·#7·#9의 선행 작업과 범위를 따른다. 주 시작 요일은 #1에서 미결정이며 현재 월요일 시안을 유지한다. [#22](https://github.com/JIHYE0705/triplog/issues/22)의 세로형 위클리는 사용자 선택 전이므로 자동 교체하지 않는다.

## UI 설계·리뷰 절차

1. **Context Analysis:** PRD·관련 Issue·AGENTS·기존 컴포넌트/스타일·결정 이력·주요 행동·실제 데이터 계약과 제약을 읽는다. 승인·제안·미구현을 구분한다.
2. **Design Exploration:** 최대 3가지 방향을 같은 현실적인 가상 기록으로 비교한다. 각 방향은 정보 구조·레이아웃·탐색·상호작용·시각 위계 중 최소 2개가 실질적으로 달라야 한다. 가능하면 같은 화면·콘텐츠·크기의 정적 목업/미리보기를 제공한다. 색상만 다른 안은 제외한다.
3. **User Approval:** 방향별 장단점·추천 이유와 변경 범위를 설명하고 선택·승인 전에 대규모 구현을 멈춘다. 기존 승인 범위는 다시 묻지 않는다. 이번 문서 구축은 이미 승인된 작업이다.
4. **Implementation:** 승인된 안을 기존 토큰·컴포넌트로 구현한다. 새 값은 이유를 남기고 API·데이터·인증·핵심 기능을 보존한다.
5. **Visual Review:** 브랜드·AI 안티패턴·위계·사진/글 비율·실제 내용의 자연스러움·모바일·접근성을 실제 브라우저 스크린샷으로 검토한다. 개인 기록 대신 가상 데이터 사용. 도구가 없으면 미검증을 보고한다.
6. **Refinement:** Critical(기능·접근성), Major(사용성·레이아웃·가독성), Minor(간격·정렬·완성도) 순으로 수정하고 재검토한다. 리뷰만 요청된 경우 수정하지 않고 개선안을 전달한다.

작은 UI 변경·버그 수정은 맥락·영향·관련 검증으로 간소화한다. 단순 색/문구 조정마다 3안·재승인을 강제하지 않는다. 설계는 `$triplog-ui-design`, 검토는 `$triplog-ui-review`를 사용할 수 있다. 저장소 스킬 경로·형식은 [OpenAI 공식 문서](https://learn.chatgpt.com/docs/build-skills)에 따른다.

검토 데이터: 긴 한글 장소명·영문 혼합·여러 줄 일기·사진 있음/없음·기록 많은 날/빈 날·여행/주/월 경계·겹치는 여행. 관련 키보드 흐름·터치 영역·200% 글자 확대와 320px 리플로우를 확인한다. 반응형 Chromium 검증과 실제 iPhone Safari·홈 화면/macOS Safari 검증은 별도 기록한다. 자동 대비 계산만으로 전체 WCAG 준수를 선언하지 않는다.

### 다음 화면 개선 추천 순서

1. **주간 + 공통 탐색 (#22):** 실제 구현이 있어 비교가 가능하다. 같은 데이터로 현행과 세로형 후보를 비교하고 320/360/390px·낮은 높이에서 7일·긴 장소명·+N개를 우선 평가한다. 공통 배경·탭·포커스 토큰 적용도 승인 범위에 포함해 제안한다. #3은 머지·종료되어 재구현 완료로 보고하지 않는다.
