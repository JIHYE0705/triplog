# Triplog 1차 개발 결정 정리

기준일: 2026-10-31 KST. 확정 요구사항과 추천·미결정을 구분한다. 세부 요구는 [PRD](PRD.md), 개발 맥락은 [인수인계](CODEX_HANDOFF.md)를 함께 읽는다.

디자인 최신 기준은 [디자인 시스템](design/DESIGN_SYSTEM.md)과 [디자인 결정](design/DECISIONS.md)에서 관리한다. 아래 컬러 HEX와 폰트 크기·굵기 초안은 이력으로 보존하며 최신 승인 기준으로 대체한다. 기본 배경은 흰색, 기존 생크림색은 보조 배경으로 해석한다. 기능·운영 정책의 미결정 상태는 유지한다.

## 확정된 제품 방향

| 항목 | 기준 |
| --- | --- |
| 형태 | 개인 비공개·아이폰 중심 모바일 우선 웹앱·PWA. 맥 브라우저에서도 같은 기록 조회·수정 |
| 이름·로고 | triplog · 개발자 터미널 앞을 지나는 비행기 |
| 화면 | 월간·주간·일간·여행·지도에서 같은 기록 조회 |
| 월간 | 기간을 잇는 옅은 가로 띠, 왼쪽 강조 세로선 없음 |
| 주간 | 종이 다이어리 한두 페이지처럼 7일 전체 보기. 장소·시간·작은 사진, 초과분 +N개 |
| 일간 | 하루 여러 방문의 사진·소감과 하루 전체 일기를 구분 |
| 지도 | 방문 장소의 사진 핀 및 일기 연결, 같은 장소 재방문 이력 |
| 디자인 | SUIT·얄쌍한 인상·생크림색 밝은 바탕·얇은 선·몽블랑 밤크림색 |
| 변경 관리 | main 직접 푸시 금지. 모든 변경은 작업 브랜치와 PR |

화면·메뉴 이름에는 '나의' 접두어를 붙이지 않는다. 다이어리·여행·지도·여행 수첩처럼 짧고 직접적인 이름을 사용한다.

공유·동행자 공동 기록은 후속 검토, 폰 캘린더 연동·네이티브 앱·실시간 이동 추적은 1차 제외다. 트리플 이관 여부는 보류다.

## 권장 기술·운영 기준안

Next.js + TypeScript / Tailwind CSS 및 다이어리 컴포넌트 / Supabase Auth(Google 로그인)·PostgreSQL·비공개 Storage / Google Maps / GitHub + Vercel.

사용자가 인수인계에 남기도록 요청한 추천 방향이다. 계정 생성·요금제 선택·실제 연동 완료를 뜻하지 않는다. 차곡과 분리한 전용 프로젝트를 사용하며, 브라우저 초안 복구와 서버 저장을 구분한다. JSON과 사진을 함께 내보내고 실제 복원으로 검증한다.

### 앱 기본 구성 착수 (2026-10-31)

사용자가 첫 기반 작업 진행을 승인해 Next.js App Router·TypeScript·Tailwind CSS로 초기화했다. SUIT 자체 호스팅·몽블랑 컬러·세 메뉴 안내 화면·PWA manifest와 아이콘·PR 자동 검사를 구성한다. 이 단계는 #2의 일부이며 인증·DB 모델·사진·지도·주간 7일 화면은 후속 구현이다. PWA 아이콘은 코드로 그린 초안이며 최종 로고 승인을 뜻하지 않는다. 설치·실행·검증 방법과 실제 구현 상태는 README에서 관리한다. 미결정 운영 정책은 계속 미확정으로 유지한다.

### 전용 Supabase 연결과 인증 보류 (2026-11-01)

차곡과 분리해 만든 서울 리전 `triplog-dev`를 연결 대상으로 사용한다. 생성 당시 Free 플랜·월 $0 조건을 확인했다. 이번 범위는 서버용 publishable key 클라이언트와 읽기 전용 연결 검사까지다. 사용자 결정으로 Google 로그인·허용 계정·계정 관리를 뒤로 미룬다. 샘플 화면은 로그인 없이 열며 실제 개인 기록 저장·사진 업로드는 아직 제공하지 않는다. 인증과 소유권 검증은 실제 비공개 데이터를 연결할 때 함께 구현한다. 기존 인증 작업과 원격 DB 적용 이력은 [연결 안내](SUPABASE_SETUP.md)에 기록한다.

## 선택이 필요한 운영 정책

| 항목 | 추천 | 상태 |
| --- | --- | --- |
| 주 시작 | 월요일 | 사용자 최종 선택 전 |
| 여행 없는 일상 기록 | 허용, 여행 연결은 선택 | 사용자 최종 선택 전 |
| 사진 원본 | 앱에는 압축본, 원본은 개인 사진 백업 유지 | 사용자 최종 선택 전 |
| 압축 이미지 크기 | 긴 변 최대 약 2,048px부터 검증 | 실제 화질·HEIC·회전·용량 검증 전 |
| 휴지통 | 30일 복구 | 제안, 영구 삭제 방식도 함께 결정 |
| 검색 | 1차 여행 제목·장소명, 본문 검색은 후속 | 사용자 최종 선택 전 |
| 같은 날 여러 여행 | 방문별로 여행 선택, 날짜만으로 자동 확정하지 않기 | 사용자 최종 선택 전 |
| 월 예산 | 호스팅·DB·사진 저장/전송·지도 호출량 확인 후 산정 | 금액 미정 |

추천을 기록하라는 요청을 모든 정책의 최종 확정으로 확대 해석하지 않는다. 결정 후 이 문서·PRD·README·이슈 #1을 함께 정리한다. 미결정 부분 외의 가역적인 작업은 진행할 수 있다.

## 추가할 개발 작업

### 사용 기기·PWA 방향 확정 (2026-10-31)

사용자는 아이폰에서 주로 사용하고 맥에서도 같은 기록을 사용할 수 있는 방향을 선택했다. 아이폰 Safari·홈 화면 실행을 우선하고 macOS Safari·Chrome 브라우저에서 조회·수정·사진 및 긴 글 정리를 지원한다. iOS·macOS 네이티브 앱과 App Store 배포는 1차에 추가하지 않는다. 웹앱·PWA 제공을 위해 Apple Developer 유료 가입을 진행하지 않는다.

같은 계정의 서버 기록·사진을 기기 간 공통 원본으로 사용한다. 서버 저장 후 다른 기기에서 다시 조회해 확인하며, 동시 수정 충돌을 감지한다. 실시간 공동편집은 범위에 추가하지 않는다.

### PWA 기본 설정

- 홈 화면 아이콘·앱 이름·시작 URL·테마와 standalone 실행 구성.
- 모바일 safe area와 하단 메뉴 확인. 홈 화면 실행에서도 주간 7일이 잘리지 않게 한다.
- 온라인 웹앱의 설치 경험부터 제공한다. PWA라는 이유로 완전한 오프라인 지도·사진 동기화를 자동 추가하지 않는다.
- 완전한 오프라인 사용과 백그라운드 사진 업로드는 1차에서 제외한다. 업로드 중 앱을 벗어났을 때 중단·실패를 안내하고 재시도할 수 있어야 한다.
- 아이폰 Safari와 홈 화면 실행에서 사진 선택·한글 입력·키보드·safe area를 확인하고 맥 브라우저에서 같은 기록을 읽고 수정하는 흐름을 검증한다. 실기기 미검증은 별도로 남긴다.
- 캐시가 개인 기록을 다른 계정에 노출하지 않게 하고 로그아웃 시 개인 임시 데이터 처리 규칙을 정한다.

### PR 자동 검사

- 선택한 스택의 의존성 설치·타입 검사·프로덕션 빌드·핵심 동작 테스트를 PR마다 실행.
- 앱 초기화 전 존재하지 않는 명령을 CI에 작성하지 않는다. 고정된 패키지 매니저와 lockfile 사용.
- 검사 코드·유효한 실행 결과를 먼저 만든 뒤 실제 체크 이름으로 main 보호에 연결.
- skip·미실행·비밀값 누락을 성공으로 오인하지 않게 보고한다.
- 브랜치 보호 설정은 대화에서 직접 적용·검증하지 못했다. CI PR만으로 보호 설정이 완료됐다고 하지 않는다.

### 기존 이슈의 완료 조건 보완

- #7: 업로드 전 사진 다중 선택 미리보기, 순서·대표 사진 선택. 파일명과 사진 방향도 확인.
- #9: 저장되지 않은 글이 있는 상태에서 날짜/화면 변경·종료 후 초안 복구. 서버 저장 완료와 구분.
- #4·#5·#6·#8: 기록 수정·삭제 시 일간·주간·월간·여행·지도 표시가 일관되게 반영. 운영 원본과 임시 UI 상태가 어긋나지 않도록 검증.
- #10: 백업 파일의 버전·사진 연결·시간대·참조 관계를 보존해 복원.

## 컬러 선택 기록 — 몽블랑 밤크림 확정 (2026-10-31)

사용자는 파란색 대신 몽블랑 디저트 위에 가늘게 짜 올린 밤크림색을 메인 방향으로 선택했다. 노란 커스터드보다 갈색과 회색이 조금 섞인 부드럽고 차분한 톤이다. 기존 파란색 중심 디자인 기준을 대체한다. SUIT의 얄쌍한 인상과 정갈한 수첩 구성을 유지한다.

### 팔레트 초안

색상 방향은 확정이며 아래 HEX 값은 실제 화면에서 조정할 초안이다.

| 역할 | 색상 | 적용 방향 |
| --- | --- | --- |
| 바탕 | 생크림색 `#FAF8F4` | 밝은 종이 바탕 |
| 메인 | 몽블랑 밤크림 `#B69A7D` | 주요 컬러 요소 |
| 옅은 강조 | 밝은 밤크림 `#EAE0D4` | 월간 여행 기간 띠·선택 배경 |
| 진한 강조 | 깊은 밤색 `#755B45` | 버튼·선택 글씨 |
| 본문 | 에스프레소색 `#37302B` | 본문·입력 글씨 |

옅은 색을 작은 글씨에 그대로 쓰지 않고 실제 배경과의 대비 및 선택·포커스 상태를 검증한다. 본문 가독성을 유지하고, 월간 기간 띠에 왼쪽 세로선을 넣지 않는다. 이 결정은 문서 기준 변경이며 기존 디자인 시안·README 헤더 SVG·실제 앱의 색상 적용 완료를 뜻하지 않는다.

## 폰트 선택 기록 — SUIT 확정 (2026-10-31)

사용자는 첫 번째 비교안 SUIT를 선택했고, 전체 인상은 “얄쌍하게”를 요청했다. 후속 비교에서도 첫 번째는 SUIT였다. IBM Plex Sans KR(후속 비교의 세 번째)은 본문 비교에서 긍정적으로 평가했지만 최종 선택은 SUIT 단일 패밀리다. 본문에 IBM을 혼용하거나 Pretendard로 바꾸지 않는다.

### 구현 기준 초안

아래 굵기·크기는 사용자 요청을 구현하기 위한 제안값이며 실제 모바일 화면에서 확인 후 조정한다.

| 요소 | 제안 |
| --- | --- |
| 패밀리 | SUIT / 웹 가변 폰트 사용 시 SUIT Variable |
| triplog 워드마크 | 400부터 검토. 굵은 볼드 대신 가벼운 획과 자간으로 정리 |
| 큰 제목·날짜 | 400 기본, 큰 제목만 300도 비교 가능 |
| 본문·입력창 | 400, 모바일 16px 기준. 본문 300 이하로 일괄 축소하지 않음 |
| 버튼·선택·소제목 | 400~500, 필요한 곳에만 500 사용 |
| 본문 행간 | 약 1.8~1.85부터 검토 |

전반적인 얇은 인상은 굵기와 여백으로 만든다. 색 대비·입력창 크기·작은 달력 숫자를 희생하지 않는다. 주간을 억지로 넣기 위해 글자 크기나 굵기를 계속 줄이지 않는다. 기존 화면의 굵은 제목·버튼·로고 스타일을 함께 점검한다.

공식 배포본과 라이선스를 확인해 적용하고 실제 앱에서는 자체 호스팅/서브셋·로딩 성능을 검토한다. 로딩 전 시스템 폴백을 SUIT가 적용된 결과로 보고하지 않는다. 생성 로고 이미지 속 글자는 CSS 폰트로 변경되지 않으므로 심벌과 SUIT 워드마크를 분리하는 방식을 검토한다.
