# Triplog 1차 개발 결정 정리

기준일: 2026-10-31 KST. 확정 요구사항과 추천·미결정을 구분한다. 세부 요구는 [PRD](PRD.md), 개발 맥락은 [인수인계](CODEX_HANDOFF.md)를 함께 읽는다.

## 확정된 제품 방향

| 항목 | 기준 |
| --- | --- |
| 형태 | 개인 비공개·모바일 우선 웹앱 |
| 이름·로고 | triplog · 개발자 터미널 앞을 지나는 비행기 |
| 화면 | 월간·주간·일간·여행·지도에서 같은 기록 조회 |
| 월간 | 기간을 잇는 옅은 가로 띠, 왼쪽 강조 세로선 없음 |
| 주간 | 종이 다이어리 한두 페이지처럼 7일 전체 보기. 장소·시간·작은 사진, 초과분 +N개 |
| 일간 | 하루 여러 방문의 사진·소감과 하루 전체 일기를 구분 |
| 지도 | 방문 장소의 사진 핀 및 일기 연결, 같은 장소 재방문 이력 |
| 디자인 | 정갈한 고딕체·흰 바탕·얇은 선·절제된 파란색. 폰트 패밀리는 선택 중 |
| 변경 관리 | main 직접 푸시 금지. 모든 변경은 작업 브랜치와 PR |

공유·동행자 공동 기록은 후속 검토, 폰 캘린더 연동·네이티브 앱·실시간 이동 추적은 1차 제외다. 트리플 이관 여부는 보류다.

## 권장 기술·운영 기준안

Next.js + TypeScript / Tailwind CSS 및 다이어리 컴포넌트 / Supabase Auth(Google 로그인)·PostgreSQL·비공개 Storage / Google Maps / GitHub + Vercel.

사용자가 인수인계에 남기도록 요청한 추천 방향이다. 계정 생성·요금제 선택·실제 연동 완료를 뜻하지 않는다. 차곡과 분리한 전용 프로젝트를 사용하며, 브라우저 초안 복구와 서버 저장을 구분한다. JSON과 사진을 함께 내보내고 실제 복원으로 검증한다.

## 선택이 필요한 운영 정책

| 항목 | 추천 | 상태 |
| --- | --- | --- |
| 주 시작 | 월요일 | 사용자 최종 선택 전 |
| 여행 없는 일상 기록 | 허용, 여행 연결은 선택 | 사용자 최종 선택 전 |
| 사진 원본 | 앱에는 압축본, 원본은 개인 사진 백업 유지 | 사용자 최종 선택 전 |
| 압축 이미지 크기 | 긴 변 최대 약 2,048px부터 검증 | 실제 화질·HEIC·회전·용량 검증 전 |
| 휴지통 | 30일 복구 | 제안, 영구 삭제 방식도 함께 결정 |
| 검색 | 1차 여행 제목·장소명, 본문 검색은 후속 | 사용자 최종 선택 전 |
| 같은 날 여러 여행 | 방문별로 여행 선택, 날짜만으로 자동 확정하지 않기 | 사용자 최종 선택 전 |
| 월 예산 | 호스팅·DB·사진 저장/전송·지도 호출량 확인 후 산정 | 금액 미정 |

추천을 기록하라는 요청을 모든 정책의 최종 확정으로 확대 해석하지 않는다. 결정 후 이 문서·PRD·README·이슈 #1을 함께 정리한다. 미결정 부분 외의 가역적인 작업은 진행할 수 있다.

## 추가할 개발 작업

### PWA 기본 설정

- 홈 화면 아이콘·앱 이름·시작 URL·테마와 standalone 실행 구성.
- 모바일 safe area와 하단 메뉴 확인. 홈 화면 실행에서도 주간 7일이 잘리지 않게 한다.
- 온라인 웹앱의 설치 경험부터 제공한다. PWA라는 이유로 완전한 오프라인 지도·사진 동기화를 자동 추가하지 않는다.
- 캐시가 개인 기록을 다른 계정에 노출하지 않게 하고 로그아웃 시 개인 임시 데이터 처리 규칙을 정한다.

### PR 자동 검사

- 선택한 스택의 의존성 설치·타입 검사·프로덕션 빌드·핵심 동작 테스트를 PR마다 실행.
- 앱 초기화 전 존재하지 않는 명령을 CI에 작성하지 않는다. 고정된 패키지 매니저와 lockfile 사용.
- 검사 코드·유효한 실행 결과를 먼저 만든 뒤 실제 체크 이름으로 main 보호에 연결.
- skip·미실행·비밀값 누락을 성공으로 오인하지 않게 보고한다.
- 브랜치 보호 설정은 대화에서 직접 적용·검증하지 못했다. CI PR만으로 보호 설정이 완료됐다고 하지 않는다.

### 기존 이슈의 완료 조건 보완

- #7: 업로드 전 사진 다중 선택 미리보기, 순서·대표 사진 선택. 파일명과 사진 방향도 확인.
- #9: 저장되지 않은 글이 있는 상태에서 날짜/화면 변경·종료 후 초안 복구. 서버 저장 완료와 구분.
- #4·#5·#6·#8: 기록 수정·삭제 시 일간·주간·월간·여행·지도 표시가 일관되게 반영. 운영 원본과 임시 UI 상태가 어긋나지 않도록 검증.
- #10: 백업 파일의 버전·사진 연결·시간대·참조 관계를 보존해 복원.

## 구현 순서

1. #1의 기술·정책 결정 및 #2 개인 로그인·데이터 기반
2. #4·#5 여행·일기 서버 저장
3. #7 사진 업로드
4. #8 실제 지도 연동
5. #9·#10 복구·백업, #11 운영 배포

#3 주간 잘림과 #6 월간 연동은 병행한다. PWA와 CI는 초기에 기반을 마련하고, 적용 여부를 검증한다. 배포·유료 결제·계정 연결을 이 문서 작성으로 완료 처리하지 않는다.

## 폰트 선택 기록

아직 미확정. Pretendard / SUIT / Wanted Sans를 같은 날짜·장소·일기 문장과 동일한 크기·굵기·행간으로 비교한다. 선택 전 시스템 폴백을 최종 폰트라고 보고하지 않는다. 최종 패밀리·굵기·본문 크기·행간은 선택 후 이 절에 기록한다. 실제 앱에서는 공식 배포본·라이선스를 확인하고 자체 호스팅/서브셋·로딩 성능을 검토한다.
